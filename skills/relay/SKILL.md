# 会話を引き継ぐ

このセッションは新しく始まったが、**同じ人物が直前まで別の場所で話していた**。
その会話を引き継いで、話が途切れないように続ける。

**要約された引き継ぎ書は使わない。** 本人が実際に打った言葉を原文のまま読む。
（引き継ぎ書は事実は残すが、温度と地雷——何に苛立ち、何に興味を示したか——を落とすため）

## 手順

### 1. まず候補を見る。当てにいかない

```bash
relay --list
```

**「続きから」だけでは、どの会話かは決まらない。** 同じ場所でも複数の会話が並行して
動いていることがある（実測: 1つの場所に90本以上）。最新を黙って採ると、
本人が始めたかったものと違う会話を持ってくる。

`codex resume` も `claude --resume` も、既定は**選択画面**で、最新を採るのは
`--last` / `-c` と明示したときだけ。同じ扱いにする。

### 2. 候補の数で分ける

| 候補 | どうするか |
|---|---|
| 1本だけ | そのまま読み込む |
| 複数 | **一覧をそのまま本人に見せて選んでもらう**。勝手に決めない（本人が自分の手で選びたいときは `relay --pick` を勧める） |
| この場所に無い | `relay --list --all` で他の場所も見る |
| 本人が「◯◯の続き」と場所を言った | `relay --list --all` から場所で絞って提案する |
| 本人が「直前の」と明示した | `relay --print --previous` でよい |

一覧を見せるときは、そのまま貼るだけでいい。番号・いつ・場所・発話数・
何の話かが並んでいるので、本人はそれで選べる。

### 3. 選ばれたものを読み込む

```bash
relay --print --from <#かref>
```

番号は一覧を出すたびに変わる。**本人とやりとりが挟まるなら ref を使う。**

出力には本人の発話（全件・時系列）、直近の経過、触ったファイル、実行コマンド、
gitの状態が入っている。

### 4. 現在地を一言だけ確認する

長い要約を返さない。「◯◯の続きですね。いま△△まで来ています」程度にとどめ、
すぐ作業に入れる状態にする。

### 5. 作業対象のリポジトリがあれば STATUS.md / KICKOFF.md を読む

会話の記録と食い違ったら、**リポジトリの方が正本**。

## 注意

- 前の会話に**未回答の質問**が残っていないか見る。あれば最初にそれへ答える
- 本人が「もうやらない」「価値がない」と言ったものを蒸し返さない（判断ログがあればそれに従う）
- **同じリポジトリで別のセッションが作業中かもしれない**。`git status` が汚れていたら、書き込む前に本人に確認する
- 秘密情報（鍵・トークン）が記録に混ざっていても、復唱しない
